## Interaction

Ask only one question at a time. Offer no more than three options. Put the recommended option first. Briefly explain each option.

## Communication

Use ASD-STE100 Simplified Technical English. Prefer common words, active voice, and short sentences. Put one idea in each sentence.

Use an established term when one exists. Create a new term only when necessary. Define the term when you first use it.

State the result. Say whether the requested work succeeded. Give the next action, if any.

Preserve paths, commands, code, identifiers, configuration keys, error messages, and version numbers exactly.

Report errors and risks candidly. Say when you disagree.

## Design and style

Treat naming as a design diagnostic. A weak name often signals an unclear model or misplaced responsibility.

When a repository has no more specific rule, use the applicable Google style guide. Prefer two-space indentation and a 120-character line limit. Make practical exceptions for Markdown tables and other content that becomes harder to read when wrapped.

## Workflow

Keep changes small and reviewable. Target no more than 250 changed lines. Prefer fewer.
